运行时端到端主链路

这条链路解释“手柄为什么不会直接控制电机”：手柄只产生速度意图，真正的关节动作由当前底层策略根据机器人反馈计算。

01 输入手柄 / CLIraw [vx, vy, wz]
02 决策Supervisor选择行为并过滤 command
03 路由BehaviorPolicies选择 locomotion / stand / Init
04 感知robot.state()读取基座和 12 个关节状态
05 推理48 → Policy → 12构造观测并执行 ONNX
06 过渡ActionBlender切策略时连续混合动作
07 控制PD + 力矩限制q_target → τ，限制 ±30 Nm
08 仿真MuJoCo.step()推进状态并回到第 04 步

Supervisor 状态机

普通切换由 command 活跃度、迟滞阈值和持续时间决定；跌倒检测的优先级高于普通行为切换。

STAND明确运动指令 → WALK指令归零 → STOPPING实际速度稳定 → STAND 任意正常状态跌倒 → INIT高度/姿态稳定 → STAND DISABLED无 Init 策略或状态异常
关键区别：状态机决定“运行哪个策略”和“给策略什么 command”，不会自己计算关节角。关节动作仍来自 stand、locomotion 或 Init policy。

建议阅读顺序

第一次看工程时，按照“接口 → 单任务 → 部署 → 上层切换”阅读，比逐文件随机浏览更容易建立完整心智模型。

STEP 1先理解公共接口bpx_base_env_cfg.py：关节顺序、观测、动作和控制频率。
STEP 2再比较三个任务观察 command、reset、reward、termination 有何不同。
STEP 3沿 sim2sim 闭环阅读run_mujoco → runner → robot / policy。
STEP 4最后理解行为切换supervisor → behaviors → transition，并结合 CSV 验证。
